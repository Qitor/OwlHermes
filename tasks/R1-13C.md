Observed UX problem:

The user manually ran Hermes in an interactive session.

Hermes returned a full final Chinese daily report in the terminal, but the Obsidian vault did not immediately show the final daily report body.

The previous explanation was that:

- live vault logging worked;
- live run directory existed;
- digest was stored in SQLite;
- user needed to run `make obsidian-export` to see the complete report in `00_Daily/`.

This is unacceptable UX.

New stronger product requirement from user:

If live Obsidian logging is enabled, **all valuable intermediate research results must be written to Obsidian in real time**, not only exported at the end.

This includes:

- source selection and source check notes;
- source run status;
- candidate findings;
- raw item / candidate summaries;
- evidence excerpts and evidence URLs;
- signal promotion notes;
- every valuable signal as its own note;
- failed source notes;
- final daily report;
- review queue entries;
- links between all related notes.

The vault must support bidirectional navigation:

- daily note links to live run;
- live run links back to daily note;
- signal notes link to candidates, evidence, source, risk domains, live run, and daily note;
- candidate notes link to source, evidence, related signals, live run, and daily note;
- evidence notes link to signal, candidate/raw item, source, live run, and daily note;
- source notes link to candidates, signals, evidence, source runs, and failures;
- failed source notes link to source note, live run, and daily note;
- live timeline links to created notes.

Core UX contract:

When Hermes says “daily report completed” in a manual or automated session, the Obsidian vault should already contain:

1. `00_Daily/YYYY-MM-DD.md` with the full final report body.
2. Live run directory under `08_Live_Runs/YYYY-MM-DD_HHMMSS/`.
3. Live source notes for checked sources.
4. Live candidate notes for valuable candidates.
5. Live evidence notes for extracted evidence.
6. Live signal notes for every promoted valuable signal.
7. Failure notes for failed sources.
8. Bidirectional links among these notes.
9. Review queue entries for missing evidence, weak signals, failed sources, or uncertain claims.

The user should not need to run `make obsidian-export` just to see the final report or intermediate notes.

`make obsidian-export` remains useful for:

- backfill;
- repair;
- full consolidation;
- index regeneration;
- migrating old DB state to Obsidian.

But it is no longer part of the normal live daily-report UX.
